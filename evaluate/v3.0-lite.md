## 2. V3 渲染管线

```text
_select（V2.1 原样：锚点解析 → relation → related 证据选择）
  → 问题焦点 focus = query 实体 ∪ 最高分锚点实体（故意不含次锚点，防跨子任务走私；
     锚点 kind=summary 时只捐强符号、不捐路径，防多任务末尾总结投毒）
  → 绑定判定 _binds：完整路径重合（只认含 "/" 的路径，裸文件名不算）
     / ≥2 强符号 / query 点名 1 + 共享 1
     （test 结果可经 inherited 绑定到它所属的工具调用链）
  → solution_status：
     bound patch + passed test → verified_solution
     bound patch               → patch_available
     bound summary             → summary_only
     有 source/error/problem/test → source_only
     仅 note 锚点              → related_only
  → 按状态渲染：分节顺序、预算（8k/8k/4k/4k/1k）、正文去重、
     补丁按时间序保留最终状态、末尾诚实声明（NOTE: ...）
  → False Solution 门禁：绑不上的 patch/test/summary 一律不渲染
```

**官方 31 条检索审计中修掉的 3 个绑定缺陷**（各带回归测试，详见
`evaluate/v3.1-vs-v2.1.md` §5）：裸文件名碰撞（core.py 跨包误绑，改为只认完整
路径）、多任务 summary 锚点投毒（改为 summary 锚点不捐路径）、note 锚点回归
（精化为只有 summary 不捐，note 照常捐）。

## 5. 已知缺口（不在 lite 范围）

1. **T5 只到 related_only**：query "add furlong imperial unit" 无路径/snake_case 实体，
   relation 退化，furlong 轨迹里的 Write/Edit 补丁没进 related。这是 V2.1 已知的
   "自然语言 query 提不出实体"问题；计划 §4 的 query 解析增强被 lite 版砍掉，留待后续。
2. **T6 仍返回 ~4k source_only**：BM25 对弱正分（8.27）照样召回，v3 只能降级包装
   （非 solution + 声明），不能过滤召回本身。
3. **T1 是 patch_available 而非 verified_solution**：to_pandas 修复的历史轨迹里
   没有找到可绑定的"通过测试"记录（当时的验证方式解析不出 passed 标记），按规则降级，
   符合"宁可降级不可谎报已验证"。
